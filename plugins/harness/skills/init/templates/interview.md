# インタビュー項目(Phase 1)

Phase 0 の調査で判明済みの項目は質問しない。推定結果を提示し、追認だけを求める。

## 必須項目

1. **プロジェクト名**(調査で推定可能なことが多い)
2. **プロジェクトの一行要約** — CLAUDE.md 冒頭に置く
3. **技術スタック**(調査で推定可能なことが多い)
4. **フェーズ成熟度** — ツーリングと厳格さの水準を決める
   - 1: プロトタイプ(最小限のルール)
   - 2: 個人・継続開発(標準のルールと運用サイクル)
   - 3: 副業・収益化(検証ゲートを厳格化)
   - 4: チーム・本番(全ルール + 共有規約)
5. **NEVER ルール候補** — 壊されたら困るプロジェクト固有の構成を 2〜5 個。
   抽象的な標語ではなく、対象を特定できる具体的な記述にする
   (良い例: 「Tailwind v4 の @theme {} ブロックを変更しない」/ 悪い例: 「設定を壊さない」)
6. **CONFIRM ルール候補** — 影響が大きく承認を要する操作を 2〜5 個
   (例: DB マイグレーション、依存追加、外部 API 仕様の変更)
7. **コマンド** — ビルド / テスト / 開発サーバー起動(調査で推定可能なことが多い)

## NEVER ルールの層分類(候補ごとに判定する)

各 NEVER 候補を以下のフローで分類し、harness-rules.json の `layer` を決める。

1. **特定ファイル・パスの編集禁止として書けるか?** → `layer: "permission"`(L1。最強・最速)
   例: 「.claude/harness-rules.json を編集しない」
2. **コマンドパターンやパスパターンの動的判定で書けるか?** → `layer: "hook"`(L2)
   例: 「force push 禁止」(command_regex)、「migration ディレクトリ配下の編集」(path_glob)
3. **ファイル内の特定領域や意味的条件が必要か?** → `layer: "advisory"`(強制なし。L3 実装後の昇格候補)
   例: 「Tailwind v4 の @theme {} ブロックを変更しない」

迷ったら上の層を試す。L1 で書けるものを L2 に置かない。

## CONFIRM の機械化(ask)の選定

- 機械化(`action: "ask", layer: "hook"`)するのは**特に重要な 2〜3 個まで**。残りは rules.md の散文 CONFIRM に留める
- 理由: ask は正常な開発作業で日常的に発火する。広く張るとダイアログ疲れ → 反射承認 → 仕組み自体の無価値化を招く
- ユーザーに「どの 2〜3 個を機械化するか」を必ず確認する
- **ask の実効性はモード依存**であることを必要に応じて説明する: 主戦場は auto/acceptEdits(自動承認中の割り込み)と bypassPermissions(deny+停止変換)。通常モードでは標準確認に紛れる

## Bash 書込 companion の提案(path_glob ルールごとに確認する)

path_glob で保護する NEVER / CONFIRM ルール(permission / hook とも)には、**Bash 経由の書き込み(`>` `>>`・`sed -i`・`tee`・`cp`/`mv` 等)を同じ action で拾う companion ルール**を付けられる。背景: 編集ツールが失敗した際、エージェントは悪意なく Bash にフォールバックすることがある(v0.2 スモークテストで実証)。

- **ハーネス自己保護(protect-harness-files 系)の companion は固定で必ず生成する**(ユーザーに確認不要。削除・改名禁止)
- **プロジェクト固有の path_glob ルールについては、ルールごとに「Bash companion も付けますか?」と確認する**。勝手に増やさない(ask の companion はダイアログ発火点を増やすため、ダイアログ疲れ対策と整合させる)
- companion の regex は「書込動詞 + 同一パイプライン区切り内のパス断片」の共起で生成する(読み出し系 cat/grep や、人間の修復手順 git checkout では発火しない形にする)。生成例はテンプレートの `{{CONFIRM_RULE_ID}}-bash` を参照
- **限界を必ず説明する**: `cd` 後の短い相対パス・変数展開・インタプリタ経由(`python -c` 等)の書込は拾えない。これはヒューリスティックであり、根本解は L3(意味判定)の守備範囲
