# Claude Code 公式8機構 リファレンス

ハーネスエンジニアリングで扱う機構の正準語彙。コミュニティの「○大構成」「○層モデル」はメンタルモデルの一例として扱い、設計の単位はこの公式8機構とする。

- 出典: Claude Code 公式ドキュメント「Extend Claude Code」
  https://code.claude.com/docs/en/features-overview
- 関連: Effective harnesses for long-running agents(Anthropic Engineering)
  https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- 確認日: 2026-06-12(公式ドキュメントは更新されるため、Claude Code のメジャー更新時に再確認すること)

## 8機構 一覧

| 分類 | 機構 | 役割と例 | ロードとコンテキストコスト | 多重定義時の挙動 |
|---|---|---|---|---|
| 知識 | **CLAUDE.md** | 毎セッション必ず読まれる永続コンテキスト。規約・「常にXせよ」ルール(例: pnpmを使う、コミット前にテスト実行) | セッション開始時に全文。毎リクエスト常駐 — だから200行以内に保つ | **加算** — 全レベル(組織/ユーザー/プロジェクト/サブディレクトリ)が同時に効く |
| 知識 | **Skills** | オンデマンドの知識・ワークフロー。`/名前`で起動、または説明文への一致で自動発動(例: `/deploy`、APIスタイルガイド) | 説明文のみ常駐、本体は使用時にロード(プログレッシブ・ディスクロージャー) | **名前で上書き**(managed > user > project) |
| 実行 | **Subagents** | 隔離コンテキストで作業し、要約だけ返すワーカー(例: 大量ファイルを読む調査タスク) | 起動時に別ウィンドウ。本体のコンテキストを汚さない | **名前で上書き** |
| 実行 | **Agent teams** | 複数の独立セッションが共有タスクリスト+相互メッセージで協調。実験的機能(例: 観点別の並列コードレビュー) | 各メンバーが独立インスタンス(トークンコスト高) | — |
| 接続 | **MCP** | 外部サービス・データへの接続(例: DB照会、Slack投稿、ブラウザ操作) | ツール名のみ常駐、スキーマは使用時 | **名前で上書き**(local > project > user) |
| 接続 | **Code intelligence** | LSP連携によるシンボル単位のナビゲーションと編集後の型診断(例: 定義ジャンプ) | 編集後・参照時のみ。ファイル全読みを置き換えるので実質節約 | 言語別プラグインとして導入 |
| 自動化 | **Hooks** | ライフサイクルイベントで**決定論的に**発火。ガードレールと自動化(例: 編集後にlint、危険コマンドをブロック) | イベント時のみ実行。コンテキストコストほぼゼロ(出力を返した分だけ) | **マージ** — 全ソースのフックが発火する |
| 配布 | **Plugins** | 上記を束ねてパッケージ化・配布する層(例: meta-harness) | 中身の機構に従う | **名前空間で共存**(`plugin名:skill名`) |

## 設計上の要点

### 多重定義時の挙動がテンプレート設計の鍵

- **加算(CLAUDE.md)**: テンプレ層とプロジェクト層が自然に共存できる
- **マージ(Hooks)**: プラグイン標準フックとプロジェクト固有フックが両方発火する
- **名前上書き(Skills / Subagents / MCP)**: プロジェクト側で同名定義を置くとテンプレを差し替えられる。拡張ポイントとして使えるが、事故の元にもなる

### 関連概念の位置づけ

- **`.claude/rules/`**: CLAUDE.md の分割先。paths フロントマターで対象ファイルにスコープでき、該当ファイルを触るときだけロードされる
- **Auto memory**: Claude が作業中の学びを自分でメモし、セッションをまたいで蓄積する機構(CLAUDE.md 系列)
- **公式の使い分け原則**: 「常に知っているべきこと」は CLAUDE.md、「時々必要な参照資料・起動するワークフロー」は Skills、「毎回必ず守らせること」は Hooks(プロンプト指示はリクエスト、フックは強制)

### コミュニティ分類との対応

ブログ等でみられる「Rule / Skills / Hooks / Memory / Feedback」のような分類は公式のものではない。対応は以下の通り。

| コミュニティ分類 | 公式機構との対応 |
|---|---|
| Rule | CLAUDE.md + `.claude/rules/` |
| Skills | Skills |
| Hooks | Hooks |
| Memory | CLAUDE.md のメモリ階層 + Auto memory |
| Feedback | 対応する機構なし。Hooks の出力・テスト実行・進捗ファイル等を組み合わせて実現する横断的な設計原則 |
